GAINZ•TRACKER

Find your iron. Chase your GAINZ.

PWA SPEC v0.1 · INSTALLABLE ON iOS SAFARI

1. Overview

GAINZ Tracker is a Progressive Web App (PWA) that uses the device's geolocation and compass to point the user toward the nearest public gym and show the distance in their preferred units. Gyms are discovered dynamically via the Google Maps Places API, queried directly from the device around the user's current position — there is no hard-coded gym list to maintain. It is installable to the iOS home screen from Safari ("Add to Home Screen") and launches full-screen in standalone mode, emulating a native mobile app — no browser chrome, its own icon and splash screen. No accounts and no backend of our own; the installed app shell and the last set of discovered gyms are cached locally, so it still opens and orients even without a connection.

2. Target Audience

Gym-focused users (primarily men chasing "GAINZ") who want the fastest, no-friction way to locate and orient toward the closest public gym while out and about — no map clutter, just a direction and a distance.

3. Core Features

📍 Geolocation
Reads current position via the browser Geolocation API and queries the Google Maps Places API for nearby gyms, then computes the distance to each.
🧭 Live Compass
A large arrow rotates to point toward the nearest gym using device heading (DeviceOrientation API).
📏 Distance Readout
Big, glanceable distance to the nearest gym, updating in real time as the user moves.
⚙️ Unit Settings
Toggle between miles and kilometers; choice is saved locally and persists between sessions.

4. Functional Requirements

  • On launch, request location and compass permissions and explain why.
  • Once a position is known, query the Google Maps Places API (Nearby Search, type=gym) around the user to discover gyms dynamically.
  • Compute the great-circle distance (Haversine) from the user to each discovered gym.
  • Select and highlight the nearest gym; rotate the compass arrow to its bearing relative to the device's current heading.
  • Display distance to the nearest gym in the user-selected unit.
  • Settings screen lets the user switch miles ⇄ kilometers.
  • Recompute direction and distance continuously as position/heading change; re-query Places when the user moves a meaningful distance.
  • Cache the latest Places results so a denied/offline lookup falls back to the last-known gyms.
  • Gracefully handle denied permissions, no signal, a failed Places call, and no nearby gyms.

5. Engaging UX (Retention)

  • Instant payoff: arrow + distance appear within seconds, no setup.
  • Bold, motivational visual identity: dark theme, hype copy, "you're 0.3 mi from GAINZ" framing.
  • Streaks & check-ins: count gym visits (proximity-detected) and keep a local streak to bring users back.
  • Haptic / visual cue when the user is closing in on the gym.
  • Personality: rotating hype phrases ("Time to lift", "Don't skip leg day").

7. PWA & iOS Behavior

  • Add to Home Screen: in iOS Safari, Share → "Add to Home Screen" installs GAINZ Tracker with its own icon.
  • Standalone launch: opens full-screen with no Safari address bar or tabs, matching a native app feel.
  • Custom icon & splash screen via apple-touch-icon and startup image; theme-color tints the status bar.
  • Offline-first: after first install the service worker serves the cached shell and the last-known gyms, so it opens and orients instantly even with no connection; a live Places refresh runs when back online.
  • iOS sensor note: Safari requires a user gesture to call DeviceOrientationEvent.requestPermission() — the app prompts with a "Enable Compass" tap on first launch.

8. Deployment

  • Host: GitHub Pages, serving the static app shell, manifest, and service worker from the repo. Gym data is fetched live from the Google Maps Places API — no gym list is stored in the repo.
  • Maps API key: a Google Maps Platform key with the Places API enabled, restricted to the gainz.messana.ai HTTP referrer so the client-side key cannot be reused on other origins.
  • Key storage (no plaintext in repo): the key is held as a GitHub Actions secret (GMAPS_KEY) and never committed. A deploy workflow injects it into a git-ignored config.js at build time, then publishes via the GitHub Actions Pages source. The key stays out of source control and git history; since a client-side key is still visible in the shipped bundle, the referrer/API restrictions and quota cap remain the real abuse protections.
  • Custom domain: gainz.messana.ai via a CNAME file in the repo + a DNS CNAME record pointing the subdomain to GitHub Pages.
  • HTTPS: "Enforce HTTPS" enabled in Pages settings — GitHub auto-issues the TLS cert, satisfying iOS's requirement for geolocation, motion sensors, and PWA install.
  • Releases: push to the published branch; bump the service-worker cache version to roll out updates.

9. Max Parallelism

Startup is designed to be concurrent rather than sequential so the user sees results as fast as possible:

  • Kick off the geolocation watch and the device-orientation listener in parallel on launch; the compass can start spinning before any gym data exists.
  • The Places nearby-search depends on a position, so it fires the moment the first fix arrives — then runs concurrently with rendering (e.g. Promise.all against the cached fallback).
  • Distance computations across all gyms run as a single vectorized pass; heavy work can be offloaded to a Web Worker to keep the compass UI at 60fps.
  • UI renders progressively — the compass shell shows immediately while data streams in.

10. Permissions & Privacy

  • Orientation/compass data stays on-device. To discover gyms, the user's coordinates are sent to the Google Maps Places API (Google's servers) — that is the only data that leaves the device, and only to fetch nearby gyms. There is still no backend of our own.
  • All preferences, streak data, and cached gym results stay in localStorage.
  • Clear permission prompts with fallback messaging if denied, and a note that gym discovery uses Google Maps.

11. Out of Scope (Provisional)

  • User accounts, social feeds, or cloud sync.
  • Turn-by-turn navigation / routing.
  • Real-time crowd or gym-hours data.
